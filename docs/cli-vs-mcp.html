How Claude reaches Ableton Live

Ableton CLI vs MCP

Both let Claude change your Live set. They differ in what sits between Claude and Live, how much Claude has to carry around to use it, whether you can undo just Claude's changes, and what can leave your computer.

Signal path

The two routes

MCP server (ahujasid/ableton-mcp)

tools over JSON-RPC
  1. You"mute the drums and pull the bass down 3 dB"
  2. your prompt
  3. Claude (Desktop or Code)All 37 tool descriptions are loaded into Claude's context when the session starts, whether you use them or not.
  4. tool call + user_prompt (your words, copied into every call)
  5. Python MCP serverAlways running alongside the AI app. Translates tool calls into socket commands.
    Telemetry and dataset modules live here. PyPI builds 1.2.0–1.3.5 uploaded prompts, track names and MIDI to the author's Supabase with no consent prompt.
  6. JSON over TCP 127.0.0.1:9877
  7. AbletonMCP Remote ScriptInside Live. No mixer setters: it can't mute a track or change its volume.
  8. Live API
  9. Ableton Liveyour set

Our CLI (ableton-pp-cli)

commands in a terminal
  1. You"mute the drums and pull the bass down 3 dB"
  2. your prompt stays with Claude
  3. Claude CodeKnows the CLI exists from a short skill file and reads --help only for the commands it needs.
  4. one shell command per step
  5. ableton-pp-cli.exeStarts, does one job, exits. Looks up "Drums" and "Bass" by name, checks ranges, records old and new values in a local journal.
    Talks only to 127.0.0.1. No telemetry, no prompt text, nothing sent to the internet.
  6. picks the right script for each command
  7. AbletonOSCUDP 11000: mixer, clips, notes, scenes, devices
    AbletonMCP scriptTCP 9877: browser, Arrangement, racks
    AbletonPPExtrasTCP 9878: ours, written from scratch
  8. Live API
  9. Ableton Liveyour set
Step through one request

"Mute the drums and pull the bass down 3 dB"

  1. Claude runs 
    ableton-pp-cli tracks --agent --select name,mute,volume_db
    and gets back only what it asked for 
    [{"name":"Drums","mute":false,"volume_db":-4.0},
 {"name":"Bass","mute":false,"volume_db":-6.0}, ...]
  2. Claude runs 
    ableton-pp-cli track mute Drums --on
    {"target":"Drums","property":"mute","before":"false","after":"true","journal_id":41}
  3. Claude runs 
    ableton-pp-cli track volume Bass --db -9
    {"target":"Bass","property":"volume","before":"-6.0 dB","after":"-9.0 dB","journal_id":42}
  4. You don't like it 
    ableton-pp-cli journal revert --last 2

    Puts Drums and Bass back exactly as they were, without touching anything you changed by hand in Live.

Four short commands. Claude reports the exact before and after values, and you can run the same commands yourself in a terminal.
  1. Claude calls 
    get_session_info(user_prompt="mute the drums and pull the bass down 3 dB")

    Your request is copied into the tool call. The server's telemetry and dataset code can record it.

  2. Claude looks for a mute or volume tool 
    no set_track_mute, no set_track_volume among the 37 tools
  3. Claude answers 
    "I can't change mute or volume with these tools.
 Please mute Drums and lower Bass by 3 dB in Live."
The request can't be done: ahujasid's server has no mixer setters. Even where an MCP tool exists, the only undo is Live's own, which mixes Claude's edits with yours.
Side by side

What changes for you

QuestionMCP serverOur CLI
How does Claude learn the tools?Every tool description is loaded into Claude's context at the start of each session.A short skill file says the CLI exists; Claude reads --help for a command only when it needs it.
What does Claude get back?Whatever each tool returns, often the full object.JSON trimmed with --select and --compact, so long sets don't flood the conversation.
Does it see my prompt?Yes. Every tool asks Claude to pass your original prompt.No. It only sees the command, like track mute Drums --on.
What leaves my computer?Depends on the build: telemetry code is present and older builds uploaded prompts, names and MIDI.Nothing. It only talks to 127.0.0.1 ports 11000, 9877 and 9878.
Can I undo just Claude's changes?Only Live's undo, which also undoes your own edits.journal revert for single changes, notes restore for overwritten clips, snapshot diff to see everything that moved.
Can I use it without an AI?Not practically; it's built for AI apps.Yes. Type commands, put them in a .bat file, or schedule them.
Can I test before changing anything?No preview mode.--dry-run on every change shows exactly what would be sent.
What runs in the background?A Python server process for as long as the AI app is open.Nothing. Each command starts, finishes and exits.
Which AI apps can use it?Any app that speaks MCP, including Claude Desktop.Anything that can run a shell command. It can also serve the same commands over MCP if you ever need it.
Fair to both

When each one is the better fit

MCP makes sense when

  • The AI app has no terminal, like Claude Desktop's chat.
  • You want tools to show up as buttons and permission prompts in the app.
  • You trust the server's code and its data handling.

The CLI makes sense when

  • You work in Claude Code or any terminal.
  • You want the same commands for yourself, scripts and Claude.
  • You want to see and undo exactly what Claude changed.
  • Nothing about your sessions should leave the machine.
The CLI is still being built. Commands shown use its planned shape; flag names may shift slightly before release. MCP facts come from reading ahujasid/ableton-mcp's source and its PyPI release history (audit, 31 October 2026).
